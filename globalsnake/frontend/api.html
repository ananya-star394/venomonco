DEVELOPER INTERFACE

VenomOncoDB REST API

The presentation layer is backed by JSON endpoints so the same evidence model can serve the website, future Android applications, dashboards and computational workflows.

BASE ENDPOINT
/VenomOncoDB/api/index.php?route=summary

For XAMPP on localhost, use the project path under htdocs. The API returns JSON and allows cross-origin GET requests for research/demo integrations.

ENDPOINTS

Small, reusable interfaces.

GET?route=summary

Returns platform counts: peptides, organisms, activity records, mechanisms, structures, publications, cell lines and cancer types.

GET?route=peptides&q=chlorotoxin

Searches peptide names, IDs, sequences, source organisms, venom groups, cancer types and cell lines.

GET?route=peptide&id=

Returns one record with sequence analysis, activity evidence, mechanisms, structures, publications and completeness fields.

GET?route=dashboard

Returns descriptive analytics used by the Insights dashboard.

GET?route=methods

Returns platform scope, source hierarchy and evidence-governance rules.

GET?route=dataset

Returns dataset readiness counts, including the source-build counts, including records awaiting venom/context curation.

EXAMPLE

Use it from JavaScript.

fetch('/VenomOncoDB/api/index.php?route=peptides&q=chlorotoxin')
  .then(response => response.json())
  .then(data => console.log(data));
APP-READY ARCHITECTURE
MySQL→PHP REST API→Web / PWA→Android wrapper→External client
The API is an interface to the evidence model, not a clinical decision engine.
FILTERED DASHBOARD

Cancer-specific evidence context

/VenomOncoDB/api/index.php?route=dashboard&cancer_type_id=1

The optional cancer_type_id parameter recalculates peptide, activity, distinct-publication and publication-timeline statistics from matching cancer-cell-line evidence.
